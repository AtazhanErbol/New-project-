# Анализ проекта «Beauty by Kabylova» — баги, риски и план улучшений

Проект: Django 5 сайт-визитка + онлайн-запись для мастера маникюра/педикюра (Астана).
Стек: Django, SQLite/Postgres, Whitenoise, vanilla JS (GSAP, AOS, Swiper, GLightbox, Flatpickr), кастомный CSS.

Ниже — полный разбор найденных багов с указанием файлов и строк, готовый промпт для исправления, и предложения по развитию продукта (функционал + дизайн).

---

## 1. Критические баги

### 1.1. Race condition при записи — возможен двойной бук-инг одного слота
`apps/booking/views.py:56-69` (`submit_booking`)

```python
slot = TimeSlot.objects.select_for_update().get(id=slot_id, is_booked=False)
...
with transaction.atomic():
    slot.is_booked = True
    slot.save()
```

`select_for_update()` вызывается **до** входа в `transaction.atomic()`. Блокировка строки в БД работает только внутри транзакции — здесь её фактически нет (на Postgres это либо тихо не сработает как лок, либо вызовет `TransactionManagementError`, если `ATOMIC_REQUESTS` не включён). Между `.get()` и началом `atomic()` есть окно, в которое два параллельных запроса могут оба прочитать `is_booked=False` для одного и того же слота и оба создать `Booking` на один и тот же `TimeSlot` (а `OneToOneField` это не остановит на уровне гонки, только при фактической записи второй INSERT может упасть по constraint, но первая `slot.save()` уже выставит `is_booked=True` без проверки, что слот не был занят кем-то параллельно).

**Исправление:** весь блок — выборка + лок + изменения — должен быть внутри одного `transaction.atomic()`.

### 1.2. Удаление мастера уничтожает историю всех его записей
`apps/booking/models.py:55` и `:81`

```python
master = models.ForeignKey(Master, ..., null=True, blank=True, related_name='timeslots', ...)  # TimeSlot.master
slot = models.OneToOneField(TimeSlot, on_delete=models.CASCADE, ...)  # Booking.slot
```

`TimeSlot.master` — `on_delete=CASCADE`. При удалении `Master` из админки удаляются **все** его `TimeSlot`, а так как `Booking.slot` тоже `CASCADE`, удаляются и все связанные `Booking` — включая подтверждённые и завершённые записи с историей клиентов. При этом `Booking.master` сделан `SET_NULL`, то есть автор явно пытался сохранить историю записей при удалении мастера, но забыл про цепочку через `slot`.

**Исправление:** `TimeSlot.master` → `on_delete=models.SET_NULL` (как и у `Booking.master`), либо запретить удаление мастера с историей записей (`on_delete=PROTECT` + soft-delete через `is_active`).

### 1.3. Нет серверной проверки, что слот не в прошлом
`apps/booking/views.py:45-73` (`submit_booking`)

Фронтенд (`booking.js`) подгружает только будущие слоты, но `submit_booking` на сервере проверяет лишь `is_booked=False`, не проверяя дату/время слота. Запрос `POST /booking/submit/` с произвольным `slot_id` прошлой даты (если слот ещё не помечен занятым) будет принят.

**Исправление:** добавить проверку `slot_dt > timezone.now()` перед подтверждением записи.

### 1.4. Нет проверки, что выбранный мастер действительно оказывает выбранную услугу
`apps/booking/models.py:40` (`Service.masters` M2M) существует, но:
- В UI (`templates/partials/_booking_form.html`) шаг 1 (мастер) и шаг 2 (услуга) никак не связаны — список услуг не фильтруется по выбранному мастеру.
- `submit_booking` (`views.py:45`) не проверяет `service.masters.filter(id=master_id).exists()`.

В результате клиент может записаться к мастеру на услугу, которую тот не делает.

**Исправление:** фильтровать `servicesList` через AJAX по `master_id` (аналогично `get_masters`/`get_available_slots`) и продублировать проверку на сервере.

## 2. Серьёзные проблемы безопасности и эксплуатации

### 2.1. Нет rate-limiting на форме записи
`django-ratelimit` есть в `requirements.txt`, но не используется ни в одном view. `submit_booking` и `get_available_slots` не защищены от флуда/спама — honeypot защищает только от простых ботов, не от целевой атаки или скрипта.

**Исправление:** `@ratelimit(key='ip', rate='5/m', block=True)` на `submit_booking`, `get_available_slots`, `get_masters`.

### 2.2. `django-debug-toolbar` в зависимостях, но не подключён
`requirements.txt` тянет debug-toolbar, но он не добавлен в `INSTALLED_APPS`/`MIDDLEWARE`/`urls.py` — мёртвая зависимость, раздувающая образ/окружение. Либо подключить (только для `development.py`), либо убрать из requirements.

### 2.3. Медиа-файлы не отдаются в продакшене
`config/urls.py:12-13` — `static()` для `MEDIA_URL` навешивается только при `DEBUG=True`. В `production.py` `DEBUG=False`, а в `STORAGES` используется обычный `FileSystemStorage`, без настройки отдачи `/media/` через nginx/whitenoise/S3. После деплоя по продакшен-настройкам фото мастеров, портфолио, аватары отзывов и hero-изображение **не будут открываться**.

**Исправление:** либо подключить раздачу `/media/` через nginx в проде, либо переехать на S3-совместимое хранилище (`django-storages`) для медиа.

### 2.4. CSP не покрывает `connect-src`/`form-action`/нет nonce для инлайн-скриптов
`config/settings/base.py:110-118` — `script-src` включает `'unsafe-inline'`, что практически нейтрализует защиту CSP от XSS (а инлайн-скрипт в `base.html:62-96` обрабатывает модалку — его можно вынести в отдельный файл и убрать `unsafe-inline`). Отсутствует `connect-src` (по умолчанию падает на `default-src 'self'`, что вообще-то ок, но не явно), отсутствует `frame-ancestors`/`form-action`.

### 2.5. `ALLOWED_HOSTS` в проде — плейсхолдер
`config/settings/production.py:3` — `default=['yourdomain.kz']`. Если переменная окружения `ALLOWED_HOSTS` не выставлена при деплое, сайт продолжит работать с заглушкой вместо явной ошибки конфигурации.

## 3. Логические и UX баги

### 3.1. Маска телефона ломает курсор/редактирование
`static/js/booking.js:170-179`

```js
phone.addEventListener('input', function(e) {
    var v = e.target.value.replace(/\D/g, '');
    if (!v.startsWith('7')) v = '7' + v;
    v = v.substring(0, 11);
    e.target.value = '+7 (' + v.substring(1, 4) + ') ' + v.substring(4, 7) + '-' + v.substring(7, 9) + '-' + v.substring(9, 11);
});
```
Курсор всегда прыгает в конец поля при любом вводе/удалении символа (не сохраняется `selectionStart`), из-за чего невозможно нормально редактировать середину номера или удалить один символ через Backspace в середине. Также при удалении всех цифр код всё равно подставляет `'7'`, не давая полностью очистить поле.

### 3.2. Мёртвый код в `get_available_slots`
`apps/booking/views.py:25-28`

```python
if master_id:
    slots = slots.filter(master_id=master_id)
elif master_id == '' or master_id is None:
    pass
```
`elif` никогда осмысленно не используется — `if master_id:` уже покрывает оба случая (`''` и `None` falsy). Не баг по поведению, но мёртвый/запутывающий код.

### 3.3. `auto_generate_slots` генерирует слоты только при создании мастера
`apps/booking/models.py:124-127` — сигнал `post_save` создаёт слоты только если `created=True`. Если мастер создан неактивным и активирован позже, слоты не появятся (нужно руками жать админ-экшен `generate_slots`). Также нет периодической задачи (cron/Celery beat) на продление сетки слотов после истечения 14 дней — без ручного действия в админке запись "тихо" перестанет работать.

### 3.4. Ошибка отправки письма клиенту блокирует письмо администратору
`apps/booking/views.py:96-110` (`_send_confirmation_email`) — оба `send_mail` в одном `try`. Если упадёт первое письмо (клиенту), письмо администратору о новой записи вообще не будет отправлено, хотя могло бы дойти.

### 3.5. Чекбокс согласия на обработку ПД не сохраняется и не валидируется на сервере
`templates/partials/_booking_form.html:70` — `required`, но это не поле модели/формы. Проверка только в браузере; при отключённом JS/прямом POST на `/booking/submit/` согласие не требуется и не фиксируется в БД (юридически нечем подтвердить, что согласие было дано).

## 4. Готовый промпт для исправления (можно отдать ассистенту/разработчику как ТЗ)

```
Контекст: Django-проект записи в nail-салон (apps/booking, apps/core, apps/portfolio, apps/reviews).
Нужно исправить следующие проблемы, сохранив текущую архитектуру (Django + vanilla JS), без лишнего рефакторинга:

1. apps/booking/views.py — submit_booking: переместить select_for_update() внутрь
   transaction.atomic(), весь цикл "прочитать слот -> проверить -> пометить занятым ->
   создать Booking" должен быть одной атомарной транзакцией с блокировкой строки слота.
   Добавить проверку, что slot.date+slot.time строго больше текущего времени
   (timezone.now()), иначе отклонять запись с понятной ошибкой.

2. apps/booking/models.py — TimeSlot.master: изменить on_delete с CASCADE на SET_NULL,
   чтобы удаление мастера не каскадно удаляло его TimeSlot и связанные Booking
   (историю записей клиентов). Создать и применить миграцию.

3. apps/booking/views.py + apps/booking/forms.py — добавить серверную проверку,
   что выбранный master_id входит в Service.masters выбранной услуги (если у услуги
   указаны мастера). На фронте (static/js/booking.js) при выборе мастера на шаге 1
   подгружать список услуг этого мастера через новый/существующий AJAX-эндпоинт
   (по аналогии с get_available_slots), скрывая недоступные услуги.

4. Подключить django-ratelimit (уже в requirements.txt) к submit_booking,
   get_available_slots, get_masters — ограничение по IP, например 5-10 запросов/мин,
   с понятным сообщением об ошибке при превышении.

5. static/js/booking.js — переписать маску телефона так, чтобы сохранялась позиция
   курсора (через selectionStart/selectionEnd) и корректно обрабатывался Backspace/Delete
   в середине номера, а также полная очистка поля.

6. apps/booking/views.py — _send_confirmation_email: разделить try/except для письма
   клиенту и письма администратору так, чтобы сбой одного не блокировал другое;
   логировать оба исключения через logging вместо молчаливого проглатывания.

7. Привести booking-форму к юридически корректному виду: чекбокс согласия на
   обработку персональных данных должен быть реальным полем формы (BooleanField,
   required=True) и сохраняться в Booking (например, поле consent_given_at) либо
   фиксироваться в логе.

8. config/settings/production.py — убедиться, что ALLOWED_HOSTS обязателен
   (без дефолтного плейсхолдера 'yourdomain.kz') — если переменная окружения не задана,
   приложение должно явно падать при старте, а не тихо запускаться с заглушкой.

9. Настроить раздачу MEDIA в продакшен-конфигурации (nginx location /media/ или
   переход на django-storages + S3-совместимое хранилище), иначе фото мастеров/
   портфолио/отзывов не будут открываться на проде.

10. Усилить CSP (config/settings/base.py): вынести инлайн-скрипт показа модалки
    из templates/base.html в static/js/*.js, убрать 'unsafe-inline' из script-src,
    использовать nonce при необходимости; добавить connect-src 'self' и
    form-action 'self'.

11. Убрать неиспользуемые зависимости (django-debug-toolbar, если не планируется
    подключать) либо подключить его только в development.py за DEBUG-флагом.

12. apps/booking/views.py — get_available_slots: убрать мёртвую ветку
    `elif master_id == '' or master_id is None: pass`.

13. Добавить периодическую задачу (Celery beat / cron + management command) на
    продление сетки TimeSlot на N дней вперёд, чтобы запись не "обрывалась"
    через 14 дней без ручного действия администратора.

Для каждого пункта: написать/обновить миграции при изменении моделей, не ломать
существующий публичный URL-контракт (booking:get_slots, booking:get_masters,
booking:submit, booking:cancel), покрыть критичные сценарии (1, 2, 3) тестами
(pytest-django или unittest: двойная запись в один слот параллельно, удаление
мастера с историей записей, попытка записи на прошедший слот).
```

## 5. Идеи по дизайну

Текущий дизайн (hero, услуги, о мастере, портфолио, как это работает, отзывы, форма записи, футер) — классическая структура лендинга для бьюти-индустрии, реализована неплохо (GSAP/AOS анимации, кастомный курсор, мультистеп-форма). Направления для улучшения:

- **Главный экран:** живое видео/Reels-фон вместо статичного фото — у бьюти-аудитории заходит лучше фото.
- **Портфолио:** добавить фильтр "до/после" (слайдер сравнения), а не просто галерею — сильно поднимает конверсию для нейл-мастеров.
- **Доверие:** блок с сертификатами/обучением мастера, счётчик "выполнено работ" уже есть в модели (`works_count`) — но не вижу секции, которая бы его эффектно подавала отдельным анимированным счётчиком (number ticker при скролле).
- **Мобильная версия:** учитывая, что аудитория бьюти-услуг в основном заходит с телефона — стоит сделать saas-style "sticky" кнопку "Записаться" снизу экрана на мобильных, всегда видимую при скролле.
- **Цветовая палитра:** в CSS используется золотой/розовый (`#C9A96E`, `#F5C6D0`) — уместно для премиум-нейл-студии; можно добавить тёмную "вечернюю" акцентную секцию (например, для блока отзывов) для визуального ритма страницы.
- **Доступность (a11y):** проверить контраст текста на золотом фоне кнопок, добавить `aria-label` на иконки соцсетей в футере, `alt` на все `<img>` (где сейчас может не хватать).
